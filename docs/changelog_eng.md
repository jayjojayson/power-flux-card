# Changelog

[🇩🇪 Deutsche Version](CHANGELOG.md)

## v_2.9

### Added
- **Multiple batteries (up to 4):** The battery section can now be extended with additional battery storages. In the editor, under "Battery" — just like for the solar systems — there is an "Add another battery" button (`entities.batteries_extra`, a maximum of 3 additional = 4 in total). Like the primary battery, each battery supports either a combined sensor (positive = charging, negative = discharging) **or** separate charge and discharge sensors; each battery also has its own SoC sensor, "Show battery power in kW" and "Invert Power Value (+/-)". **The pipe always shows the sum of all batteries**, so you can see at any time how many watts all batteries are charging or discharging in total. The aggregation applies to all views (standard, horizontal, diamond, boxes and the compact view).
- **Two display styles for the battery bubble (each via a switch, mutually exclusive):**
  - **Ring segments** (`battery_split_ring`): The circle is divided into equal, thin arcs along the edge — each arc fills according to the SoC of one battery (segments ≤ 20 % are shown in red). The bubble content stays like all other nodes: icon on top, name/secondary in the middle, average SoC at the bottom. In box mode ("Rounded boxes instead of circles") the ring follows the rounded rectangle outline instead of a circle.
  - **Quarter circle / "pie"** (`battery_split_quarters`): The circle is divided into sectors and is **always completely filled** (no empty quarters): 2 batteries = two halves, 3 = two upper quarters + lower half, 4 = four quarters. Each sector shows only the SoC number of its battery (colored by charge level, ≤ 20 % red) — no icon, no name. The combined average SoC is shown large in the center.
- **Grid threshold (W) (idea from @MartB's fork):** New input field at the very bottom of the editor's Grid tab (`grid_threshold`, 0–500 W, step 5, default 0 = off) with a short info text. Grid import or export below the threshold is treated as 0 W (import and export are checked separately). This prevents the grid bubble from constantly flipping between import and export when the grid is balanced (only a few watts of fluctuation around 0). Applies to the standard and the compact view and to all sensor variants (combined sensor, separate export sensor, "Invert Power Value", kW unit); the house consumption is calculated from the cleaned grid values. Without a value, everything stays as before.

### Fixed
- **Label switch now also works when a secondary sensor is set:** The "Show label instead of secondary entity" switch (Solar/Grid/Battery) previously had no effect when a secondary sensor was configured — the secondary value was always shown. If the switch is now on, the configured label is shown instead and the secondary value is hidden. Without the switch, everything stays as before (secondary takes priority), so it is fully backward compatible.
- **Compact view — custom icons for the main entities (Discussion #85):** The compact view used fixed icons for Solar, Grid, Battery and House; the icons set in the editor (`solar_icon`, `grid_icon`, `battery_icon`, `house_icon`) had no effect there. They are now applied in the upper/lower brackets **and** in the details list. Purely additive — without a configured icon, the previous default icons are kept. Labels stay as before (details list only, not in the graphic), colors already worked.
- **Second/third sensor with the unit Wh:** Values in Wh were displayed as power (e.g. 2100 Wh as "2.1 kW", 350 Wh as "350 W"). They now keep their energy unit (Wh, from 1000 Wh as kWh).
- **Default label for consumers 4 and 5 translated:** Without a custom label, the standard view showed a fixed "Consumer 4"/"Consumer 5". It now uses the translated name like the compact view does ("Cons. 4"/"Cons. 5", German "Verbr. 4"/"Verbr. 5").
- **Compact view — text color in the export segment:** The text color depended on the export *bubble* color instead of the export *text* color. With only the bubble color set, the value had the same color as the segment and was unreadable; a text color set on its own was ignored. It now behaves like Solar, Grid and Battery: black unless a text color (`color_text_export`) is set.
- **Resizing after the card was moved:** When the card was moved or re-attached in the dashboard, the width measurement (ResizeObserver) stayed switched off permanently, so scaling and the compact view no longer adapted to later size changes. The measurement is now re-enabled when the card is attached again.

### Changed
- **Version raised to v_2.9** (console banner).
- **Editor labels clarified:** "Show Battery in kW" → "Show battery power in kW"; "Show Label in Bubble" → "Show label instead of secondary entity" (de/en).
- **Hint text at the battery "Invert Power Value (+/-)" switch:** short editor hint (`editor.invert_battery_hint`) explaining that integrations with the opposite sign (e.g. GivTCP, Solax) are switched here — the default remains "charging positive, discharging negative".
- **Default icons for consumers 4 and 5:** Without a custom icon, they now show the same icons in the standard view as in the compact view (`mdi:flash` and `mdi:lightbulb`). A custom icon and "Hide Consumer Icons" still take priority.
- **Documentation (README EN/DE) reworked:** `card_mod` was replaced by its successor **UIX (UI eXtension)** — installation/migration described, all styling examples now use the `uix:` key (contents unchanged). The feature list is complete (including multiple batteries, multiple solar sensors, grid threshold), and the configuration is explained page by page of the editor, including a YAML reference, an example and troubleshooting.
- **English changelog added:** `docs/changelog_eng.md` (the German version stays in `docs/CHANGELOG.md`).
- **Code cleaned up (no functional change):** Removed code that was no longer used — two old color picker functions including their CSS in the editor, an unused helper, unused variables/parameters, the CSS variable `--export-purple`, two unused translation keys and duplicated comments. The rendering is unchanged.
- **Performance — selective re-rendering:** Home Assistant notifies the card about every state change in the whole system, and until now the card redrew each time. It now only redraws when one of its own sensors (everything under `entities`, including additional solar systems and batteries), the configuration, the card size, the language or the theme changes — and then still immediately. As a safety net, unrelated changes trigger a refresh at most every 2 seconds so that colors set from outside (e.g. UIX templates) stay up to date.

### Notes
- **Fully backward compatible:** Configurations with exactly one battery look unchanged; the split only applies from the second battery **and** only if one of the two switches is on. The existing keys (`battery`, `battery_charge`, `battery_discharge`, `battery_soc`, `battery_label`, `battery_unit_kw`, `invert_battery`) remain the first battery.

## v_2.8

### Fixed
- **Export text color in the bar segment of the compact view (PR #79, thanks to @smoki3):** The value in the export segment was hard-coded to white text, regardless of the configured color. Like Solar, Grid and Battery, it now uses the configured text color (`color_text_export`).

### Added
- **Multiple solar systems:** Under Solar/PV, "Add another solar system" lets you add any number of additional solar sensors (`entities.solar_extra`), e.g. for multiple inverters. All configured solar sensors are summed and shown as one combined solar value (standard, horizontal, diamond and compact view). This only affects the power display; click/more-info still opens the first configured sensor.
- **Custom icon for export:** New "Export icon" field in the editor's Grid tab (`export_icon`). Replaces the fixed `mdi:arrow-right-box` in the upper/lower bracket and in the compact view's detail icon with a freely selectable icon. Without a value, the previous default icon is kept, so existing configurations look unchanged.
- **Force one unit for all values:** Two new switches "Always show values in Watt" (`force_watt_display`) and "Always show values in kW" (`force_kw_display`) in the editor group "Pipes & Consumers". This fixes the display to a single unit regardless of the value. The two switches are mutually exclusive. If both are off, the previous automatic display remains (up to 1000 W in watts, above in kW).
- **Show producers at zero watts:** New switch (`show_producer_always`) directly below "Show Consumers at zero watts" in the editor group "Pipes & Consumers". When disabled, Solar and Grid are hidden as soon as they fall back to 0 W — analogous to the existing behavior of consumers. Enabled by default so nothing changes for existing configurations. For the battery, disabling the switch additionally reveals a slider "Hide battery below charge level (%)" (`battery_hide_soc_threshold`) — since the battery node shows the state of charge and its power can be positive or negative depending on charge/discharge direction, hiding is based on the SoC rather than the wattage. The slider is only visible while "Show Producers at zero watts" is switched off.

### Changed
- **Version raised to v_2.8** (console banner).
- **Field label in the Solar tab corrected:** The entity field was wrongly called "Combined Battery Sensor (W)" (copied from the Battery tab) and is now correctly called "Solar Sensor (W)".

## v_2.7

### Fixed
- **Solar→Battery pipe is no longer hidden (regression from v_2.5):** With "Hide Inactive Pipes" switched off, the pipe still disappeared as soon as no current was flowing — and the card changed its height in the process, which caused constant "jumping" when the charging current was borderline. The pipe now stays permanently visible as long as "Battery charge via house consumption" is **disabled**. If that option is **enabled**, the pipe is deliberately not drawn (the energy then flows via the house). The reserved space follows the pipe's visibility exactly, so the tile height and width stay constant. Applies to the standard, horizontal and diamond views.
- **Compact view — bar exceeded 100 %:** With "Battery charge via house consumption" enabled, the battery charge was counted twice (once in the house consumption, once as its own bracket) — the lower brackets reached up to 150 % of the bar width. The charge is now subtracted from the house share. In addition, all bar and bracket widths are hard-limited to the total width, so an overflow is impossible even with briefly contradictory sensor values. The card width is also measured immediately on first render instead of being estimated at 400 px — this fixes the cases that only looked correct "after a page refresh".
- **Compact view — mixed languages:** The labels were hard-wired ("Grid", "House", "Battery", "Export", "In"/"Out"). They are now translated and also adopt the individual names from the main sections (e.g. "Netz" instead of "Grid").
- **Color fields only partially worked in the compact view:** The colors were hard-bound to individual variables there — "Pipe" and "Secondary" had no effect at all, and Export and House did not consistently use their configured roles. Each color role now has a defined target in the compact view: **Bubble** = bar segment, **Pipe** = bracket line, **Icon** = symbols, **Text** = value, **Secondary** = label in the details list — for Solar, Grid, Export, House, Battery and all consumers. The bracket line still follows the icon color as long as no pipe color is set, so existing configurations look unchanged.
- **Pipe threshold hid too much:** "Hide pipe at low power" also hid the consumer's bubble/box below the threshold and was therefore functionally identical to the standby switch. It now hides **only the pipe** as named; the bubble stays visible. To hide a consumer completely, use the standby threshold.

### Added
- **CSS variables for font sizes and circle size** (Discussion #74): `--font-size-value`, `--font-size-label`, `--font-size-secondary`, `--font-size-flow`, `--icon-size` and `--circle-size` can be set via card_mod to scale text and icons independently of the zoom.
- **Standby threshold for all 5 consumers** (Discussion #57): New switch "Hide standby values" (`consumer_N_standby`) with a slider (`consumer_N_standby_threshold`, 0–100 W in 1 W steps). Values below the threshold count as 0 W, so devices on standby (e.g. 1–3 W) are hidden completely. Complements the existing pipe threshold, which is meant for larger power levels.
- **Export color split up:** Instead of a single field, the Grid tab now has a complete row with Bubble, Pipe, Text, Icon and Secondary (`color_export`, `color_pipe_export`, `color_text_export`, `color_icon_export`, `color_secondary_export`). Bubble colors the grid circle while exporting, Pipe the export pipe, Text the value, Icon the symbol and Secondary the label in the compact view's details list — so value and label can be set separately there. All roles automatically follow the bubble color until they are set explicitly, so existing configurations look unchanged.
- **Third sensor (display only):** For all five additional consumers and the total consumption, a third sensor can be configured next to the second one (`tertiary_consumer_1` … `tertiary_consumer_5`, `tertiary_house`). Both values share one line, separated by " / ", and use the secondary color together. Available in all variants of the standard view (standard, horizontal, diamond, boxes). As soon as both values are shown, the line automatically switches to a smaller font without line break (`--font-size-secondary-dual`, default 8 px or 9 px in box mode), so it no longer wraps or extends beyond the node.
- **Compact view — neon glow:** New option `compact_glow` enables the glow effect in the compact view as well (bar, brackets and icons).
- **Compact view — separate battery colors:** When the compact view is active, the Battery tab shows **two complete rows** instead of one color row — one for discharge and one for charge, each with all five roles (Bubble, Pipe, Text, Icon, Secondary). In the compact view they mean: Bubble = bar segment, Pipe = bracket line, Text = value, Icon = symbol, Secondary = label in the details list. The standard views still show the usual single color row, so no ineffective fields are displayed. New keys: `color_[pipe_|text_|icon_|secondary_]battery_charge` and `…_discharge`.
- **Compact view — place icons on the bracket line** (suggested in PR #75, thanks to @smoki3): New switch `compact_icons_in_bracket` in the editor block "Compact View (evcc)". By default the icons stay inside the brackets as before and the bracket line runs unbroken. When the option is on, the icons move to the center of the bracket line and interrupt it — top and bottom. This only affects the presentation; all click targets and colors stay unchanged.
- **Compact view — export in the bar** (from PR #67, thanks to @smoki3): New option `compact_bar_selfuse`. When off, the middle bar shows only the sources at full height and the export appears only as a bracket below. When on, the export moves into the bar as its own segment, and Solar/Battery show only the share actually used in the house. The brackets at the top still show the full sources. The default remains the previous presentation.

### Changed
- **Version raised to v_2.7** (console banner).
- **Consumer list in the editor is collapsible:** Under "Additional Consumers", "Total Consumption (optional)" stays permanently open; the five consumers are now collapsed and can be opened by clicking the header (only one at a time). The header also shows the assigned label or the entity, so you can find the consumer you are looking for even when collapsed.
- **Editor code slimmed down:** The five almost identical consumer blocks were merged into one shared building block — new consumer options therefore automatically apply to all five.

## v_2.6

### Fixed
- **Horizontal view:** The connection line from Solar to Grid is now drawn as an arc (like Battery→Grid) instead of a straight line.
- **Horizontal view — Solar→Battery pipe:** The arc previously ran straight through the bubble column (over the Grid circle). It now docks at the outer edges of Solar and Battery as in the vertical view and runs through a 50 px wide left lane, around the outside of Grid. The lane is dynamic (mirror image of the vertical behavior above): only when the arc is visible does the content shift to the right — otherwise the content fills the card completely as before.
- **Diamond view — flow rate positions:** The values on the pipes (switch "Show Flow Rates (W) on pipes") now sit correctly on their pipes: Solar→House above the crossing Grid→Battery pipe, Solar→Battery and Solar→Grid (export) directly on their arcs, Grid→Battery to the left of the Solar→House line instead of in the middle of it.
- **Inactive pipes in diamond/horizontal view:** With "Hide Inactive Pipes" switched off, the Solar→Grid export pipe now stays visible as an inactive arc (previously it lay exactly on top of the import line). In the diamond view, the Solar→Battery arc also stays visible so that the diamond ring is drawn completely; in the horizontal view it is deliberately still hidden.

### Added
- **Invert grid value:** New switch "Invert Power Value (+/-)" in the editor's Grid tab (`invert_grid`). For inverters that report export as positive and import as negative.
- **Invert sensor value for all consumers:** The invert switch, previously available only for consumer 1, now exists for all 5 consumers (`invert_consumer_2` to `invert_consumer_5`). When the inverted value becomes negative, the animation direction reverses — the consumer then visibly feeds into the house (e.g. for a second solar/hybrid inverter as a "consumer").
- **Pipe threshold for all consumers:** The "Hide pipe at low power" function including the threshold slider, previously available only for consumer 1, now exists for all 5 consumers (`consumer_2_hide_pipe` … `consumer_5_hide_pipe` and the corresponding `_pipe_threshold` values). Below the threshold the entire consumer is hidden (except when "Show Consumers at zero watts" is active).
- **Compact view (evcc): all consumers:** Instead of only consumer 1 ("EV"), all 5 additional consumers are now shown in the compact view — in the lower brackets, in the bar split and in the details overview (Out column), each with its configured icon, label and color.
- **Diamond view:** The layout from PR #46 is now available as its own option (`diamond_view`): Solar on top, Grid left, Battery right, House at the bottom. Mutually exclusive with the horizontal view (the editor switches the other option off).
- **Boxes instead of circles:** New option `use_boxes` — all nodes are drawn as boxes with rounded corners instead of circles. In the standard and horizontal views the path docking points already lie on the edge midpoints; for the diagonal docking points of the diamond view, adapted paths are used in box mode so that the lines start exactly at the box edge. The donut ring also follows the box radius.

### Changed
- **Box mode typography:** With rounded boxes enabled, the extra space is used: main value 17 px instead of 15 px, second sensor 12 px instead of 10 px, both texts shifted 3 px further down.
- **Version raised to v_2.6** (console banner).
- **Card editor tidied up:** The "Appearance & Options" area is now divided into four visually separated groups: "Layout & View" (Horizontal, Diamond, Boxes, Zoom), "Effects & Appearance" (Neon Glow, Comet Tail, Dashed Line, Donut, Background, Text colors), "Pipes & Consumers" (inactive pipes, consumers at 0 W, hide icons) and "Compact View (evcc)" (activation + details now together in one block).
- README updated: note about up to 5 instead of 3 additional consumers, new options documented (Invert Grid, Invert Consumer, Hide Pipe for all consumers, compact view support).

### Notes

- PR #59 ("Hide consumer based on threshold value"): incorporated and adapted to the current code base (threshold logic corrected so that it only applies when the switch is on).
- PR #58 ("honor consumer_1_icon in compact_view"): not merged, covered by the general consumer support in the compact view (all 5 instead of only consumer 1).
- PR #46 ("Diamond layout"): incorporated afterwards as the standalone option `diamond_view` (instead of replacing the standard layout as in the PR), including adaptation to the horizontal view and box mode.
